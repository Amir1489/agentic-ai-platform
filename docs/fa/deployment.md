# راهنمای استقرار

رابط کاربری روی GitHub Pages میزبانی می‌شود. بک‌اند FastAPI به‌صورت جداگانه روی Render قرار دارد و از PostgreSQL در Supabase استفاده می‌کند.

## پایگاه داده — Supabase
۱. پنل Connect پروژه را باز کنید.  
۲. روش اتصال Session Pooler را انتخاب و URI آن را کپی کنید.  
۳. URI را به‌صورت محرمانه در متغیر محیطی `DATABASE_URL` در Render ذخیره کنید.  
۴. اگر گذرواژه پایگاه داده تغییر کرد، متغیر محیطی Render را به‌روزرسانی و بک‌اند را مجدداً منتشر کنید.

اعتبارنامه پایگاه داده را در فایل منبع، commit گیت‌هاب، متغیرهای فرانت‌اند یا issue عمومی قرار ندهید.

## بک‌اند — Render
فایل ریشه `render.yaml` سرویس وب FastAPI را تعریف می‌کند. هنگام شروع، دستور `alembic upgrade head` پیش از Uvicorn اجرا می‌شود.

متغیرهای لازم:
- `DATABASE_URL`: URI خصوصی PostgreSQL Session Pooler.
- `CORS_ORIGINS`: مبدأ دقیق فرانت‌اند؛ در حال حاضر `https://amir1489.github.io`.

مسیر سلامت فرایند `/api/health` است. بررسی سلامت Render از `/api/ready` استفاده می‌کند؛ این مسیر `SELECT 1` اجرا کرده و هنگام عدم دسترسی پایگاه داده HTTP 503 برمی‌گرداند. مسیر `/api/capabilities` فقط وضعیت پیکربندی قابلیت‌های مبتنی بر AI را گزارش می‌کند.

## فرانت‌اند — GitHub Pages
۱. در مسیر Repository Settings → Secrets and variables → Actions → Variables، مقدار `VITE_API_URL` را برابر مبدأ عمومی HTTPS بک‌اند و بدون اسلش انتهایی قرار دهید.  
۲. پس از تغییر متغیر، گردش‌کار **Deploy frontend to GitHub Pages** را اجرا کنید.  
۳. موفقیت گردش‌کار را بررسی کنید.

`VITE_API_URL` پیکربندی عمومی زمان ساخت است، نه راز. گذرواژه، کلید خصوصی API یا توکن نشست را در هیچ متغیر `VITE_*` قرار ندهید.

## آزمون سریع پس از استقرار
۱. رابط منتشرشده را باز کنید.  
۲. یک حساب آزمایشی ثبت و وارد شوید.  
۳. پروژه‌ای ایجاد کنید.  
۴. صفحه را تازه‌سازی و بازیابی نشست و پروژه را بررسی کنید.  
۵. به خانه برگردید، صفحه را تازه‌سازی و ماندن زبانه Home را بررسی کنید.  
۶. با حساب دوم وارد شوید و جداسازی پروژه‌ها را بررسی کنید.  
۷. خارج شوید و بررسی کنید مسیرهای محافظت‌شده توکن قدیمی را رد کنند.

## محدودیت‌های عملیاتی شناخته‌شده
- سرویس‌های رایگان Render ممکن است در زمان بی‌کاری متوقف شوند و نخستین درخواست با تأخیر پاسخ دهد.
- Alembic پیکربندی شده و Render پیش از شروع سرویس مهاجرت‌ها را اجرا می‌کند. خط پایه اولیه تکرارپذیر است و نصب‌های مبتنی بر `create_all` را بدون حذف داده می‌پذیرد. تغییرات آینده باید به‌صورت migration رو به جلوی مستقل ثبت و پیش از انتشار در برابر نسخه پشتیبان آزموده شوند.
- تأیید ایمیل، بازیابی گذرواژه، محدودسازی نرخ، پایش و محافظت عملیاتی در برابر سوءاستفاده پیاده‌سازی نشده‌اند.
- بررسی‌های عملیاتی دوره‌ای هر شش ساعت اجرا می‌شوند؛ موفقیت اتصال زنده پایگاه داده باید با اجرای اخیر کنترل شود.
- توکن Bearer مرورگر در این نسخه آلفا در `localStorage` ذخیره می‌شود.
