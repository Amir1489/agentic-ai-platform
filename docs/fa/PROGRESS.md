## تغییرات جدید — ۱ نوامبر ۲۰۲۶

- صف Task در پایگاه داده به‌عنوان نقطه پایدار انتظار استفاده می‌شود.
- API ایجاد Task اکنون HTTP 202 و وضعیت اولیه `queued` برمی‌گرداند.
- Worker پس‌زمینه Task را با UPDATE شرطی claim می‌کند؛ این روش از claim هم‌زمان یک Task توسط چند نمونه جلوگیری می‌کند.
- مسیر جزئیات Task برای polling اضافه شد و داشبورد وضعیت را تا پایان پیگیری می‌کند.
- آزمون‌های موفقیت و شکست ارائه‌دهنده برای چرخه صف/Worker بازنویسی شدند؛ نتیجه CI پس از اجرای گردش‌کار باید در همین بخش ثبت شود.
- محدودیت مهم: بازیابی Taskهای باقی‌مانده در وضعیت `running` پس از توقف ناگهانی فرایند هنوز وجود ندارد.
