# نقشه راه محصول و معیارهای پذیرش

## جهت‌گیری محصول
ساخت محیط کاری قابل‌اعتماد و دوزبانه فارسی/انگلیسی برای ایجاد عامل، اتصال ابزارهای تأییدشده، اجرای کارهای تحت نظارت، مشاهده تاریخچه اجرا و مدیریت پروژه‌ها و گفت‌وگوها.

تا زمانی که محیط اجرا، مجوزها، اجرای ابزار، تاریخچه ممیزی و مدیریت خطا ایجاد و آزموده نشده‌اند، پلتفرم نباید سامانه‌ای کاملاً خودمختار معرفی شود.

## مرحله صفر — زیرساخت و استقرار
**وضعیت: پیاده‌سازی شده؛ بررسی عملیاتی همچنان لازم است**

معیارهای پذیرش:
- ساخت React/Vite در CI.
- موفقیت آزمون‌های FastAPI در CI.
- تکمیل انتشار GitHub Pages.
- مسیر سلامت Render در محیط عملیاتی پاسخ‌گو باشد؛ گردش‌کار smoke تنظیم شده و بررسی زنده باید دوره‌ای انجام شود.
- مسیر آمادگی پایگاه داده پیاده‌سازی و در آزمون بک‌اند پوشش داده شده؛ اتصال زنده Supabase باید تأیید شود.
- اتصال عملیاتی Supabase بدون افشای اعتبارنامه بررسی شود.
- مهاجرت پایه Alembic پیش از شروع Render اجرا و در CI تکرارپذیر باشد.
- CORS فقط مبدأهای صریحاً پیکربندی‌شده را مجاز بداند.

## مرحله یک — حساب‌ها، پروژه‌ها و گفت‌وگوها
**وضعیت: هسته پیاده‌سازی شده؛ سخت‌سازی باقی است**

معیارهای پذیرش:
- ثبت‌نام ورودی نامعتبر و حساب تکراری را رد کند.
- گذرواژه‌ها هش شوند و گذرواژه خام ذخیره نشود.
- ورود، دریافت کاربر جاری، خروج و نشست منقضی آزموده شوند.
- کاربر نتواند منابع کاربر دیگر را فهرست، مشاهده، ویرایش یا حذف کند.
- CRUD پروژه بین نشست‌ها پایدار بماند.
- تاریخچه گفت‌وگو ذخیره شود و خطای ارائه‌دهنده پیام یتیم کاربر ایجاد نکند.
- UI حالت‌های بارگذاری، خالی، خطا، تلاش مجدد و عملیات هم‌زمان را مدیریت کند.
- پیش از انتشار عملیاتی، تأیید ایمیل، بازیابی گذرواژه، ابطال نشست، محدودسازی نرخ و راهبرد کوکی امن اضافه شوند.

## مرحله دو — مدیریت عامل
**وضعیت: بخشی پیاده‌سازی شده است**

معیارهای پذیرش:
- [x] ایجاد، فهرست، ویرایش، توقف، ادامه و حذف رکورد پیکربندی عامل.
- [ ] اعتبارسنجی کامل فرم، صفحه‌بندی و پوشش قوی آزمون مرورگر انتها‌به‌انتها.
- پیکربندی عامل در سرور اعتبارسنجی و به مالک محدود شود.
- هویت عامل، انتخاب مدل، دستورالعمل سیستم، ابزارهای فعال و محدودیت‌ها ذخیره شوند.
- وضعیت‌های draft و active از هم متمایز باشند.
- اقدامات خطرناک یا خارجی به تأیید صریح برای هر اقدام نیاز داشته باشند.
- UI حالت‌های خالی/بارگذاری/خطا و اعتبارسنجی روشن داشته باشد.

## مرحله سه — محیط اجرا و وظایف عامل
**وضعیت: MVP تک‌مرحله‌ای اولیه پیاده‌سازی شده؛ محافظت و هماهنگ‌سازی باقی است**

معیارهای پذیرش:
- [x] رکورد پایدار کار با وضعیت running/succeeded/failed برای اجرای محدود تک‌مرحله‌ای مدل.
- [x] رویدادهای append-only برای started/succeeded/failed.
- [ ] ماشین حالت کامل queued/awaiting-approval/cancelled و worker پس‌زمینه.
- [x] مهلت درخواست ارائه‌دهنده و محدودیت سخت ورودی/خروجی.
- [ ] بودجه توکن/هزینه هر کاربر، تلاش مجدد با backoff، لغو و بازیابی کار گیرکرده.
- محافظت idempotency برای عملیات تکرارشده.
- اجرای دلخواه shell/code در نسخه اولیه مجاز نباشد.
- فهرست مجاز ابزارها، اعتبارسنجی ورودی و اعتبارنامه با حداقل سطح دسترسی.
- ردپای روشن تصمیم مدل، فراخوانی ابزار، خروجی و خطا.
- دروازه تأیید انسانی برای ارسال پیام، انتشار، حذف، هزینه‌کرد یا اقدام مهم دیگر.

## مرحله چهار — ثبت ابزار و یکپارچه‌سازی‌ها
**وضعیت: پیاده‌سازی نشده است**

معیارها:
- طرح ابزار نسخه‌بندی‌شده با ورودی/خروجی نوع‌دار.
- مجوز اختصاصی هر کاربر و ذخیره رمزگذاری‌شده اعتبارنامه.
- دامنه مجوز ابزار و امکان لغو دسترسی.
- مهلت اجرا، سهمیه، خطای ساختاریافته و رویداد ممیزی.
- ابزارهای mock برای CI؛ آزمون یکپارچه‌سازی به حساب واقعی خارجی وابسته نباشد.
- دفاع SSRF و prompt injection برای ابزارهای دریافت محتوای خارجی.

## مرحله پنج — هماهنگ‌سازی گردش‌کار
**وضعیت: پیاده‌سازی نشده است**

معیارها:
- کاربر بتواند کار را از گام‌های اعتبارسنجی‌شده ترکیب کند.
- شاخه‌بندی، تلاش مجدد، مهلت اجرا و گره تأیید صریح وجود داشته باشد.
- نسخه گردش‌کار و تاریخچه اجرا ذخیره شود.
- محدودیت اجرا از حلقه بی‌نهایت و هزینه کنترل‌نشده جلوگیری کند.
- ادامه/بازپخش در صورت امکان قطعی و قابل پیش‌بینی باشد.

## مرحله شش — تنظیمات، مشاهده‌پذیری و عملیات
**وضعیت: جزئی / پیاده‌سازی‌نشده**

معیارها:
- تنظیمات پروفایل، زبان، ظاهر، نشست و ارائه‌دهنده.
- پس از ذخیره، هیچ راز یا کلیدی به مرورگر برنگردد.
- log ساختاریافته به‌طور پیش‌فرض اعتبارنامه و محتوای حساس را حذف کند.
- سلامت API از آمادگی پایگاه داده/ارائه‌دهنده تفکیک شود.
- پایش خطا، معیارها، هشدار، تمرین پشتیبان‌گیری و بازیابی.
- سیاست خروجی داده و حذف حساب.

## مرحله هفت — آمادگی انتشار
**وضعیت: در انتظار**

بررسی‌های لازم:
- مجموعه آزمون واحد، API و یکپارچه‌سازی بک‌اند.
- typecheck و ساخت تولید فرانت‌اند.
- آزمون مرورگر برای ثبت‌نام، ورود، خروج، CRUD پروژه، تاریخچه چت و ناوبری واکنش‌گرا.
- ممیزی دسترس‌پذیری: صفحه‌کلید، برچسب‌ها، کنتراست و کاهش حرکت.
- بازبینی امنیت: مجوزدهی، اعتبارسنجی ورودی، CORS، محدودسازی نرخ، اسرار و وابستگی‌ها.
- ممیزی کارایی: اندازه bundle، تأخیر API، الگوی پرس‌وجوی DB و صفحه‌بندی.
- آزمون smoke محیط عملیاتی برای فرانت‌اند، بک‌اند و پایگاه داده.
- مستندسازی محدودیت‌ها، روش بازگشت و یادداشت انتشار.

## اولویت‌بندی
۱. اصلاح صحت و امنیت زیرساخت فعلی.  
۲. افزودن آزمون تکرارپذیر و شواهد CI.  
۳. تکمیل CRUD عامل و محیط اجرا با مرزهای مجوز سخت‌گیرانه.  
۴. افزودن ابزار و گردش‌کار پس از ایجاد محافظت‌های محیط اجرا.  
۵. تکمیل تنظیمات و سخت‌سازی عملیاتی.  
۶. انجام آزمون انتها‌به‌انتها، امنیت، دسترس‌پذیری و کارایی پیش از انتشار.
