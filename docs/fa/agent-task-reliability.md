# قابلیت اطمینان اجرای Agent Task

## Lease و heartbeat
هر Task در زمان claim یک شناسه worker، زمان claim، زمان آخرین heartbeat و زمان انقضای lease دریافت می‌کند. worker در طول درخواست مدل هر ۱۵ ثانیه lease را تمدید می‌کند؛ lease پس از ۹۰ ثانیه بدون heartbeat منقضی می‌شود.

## بازیابی و تلاش مجدد
worker در هر چرخه Taskهای running با lease منقضی‌شده را بررسی می‌کند. Task تا سقف ۳ تلاش مجدداً به صف برمی‌گردد و پس از رسیدن به سقف تلاش failed می‌شود. رویدادهای recovered، retry و failed در تاریخچه ثبت می‌شوند.

## مالکیت اجرا
claim با UPDATE شرطی انجام می‌شود. heartbeat و ثبت نتیجه فقط در صورتی مجازند که Task هنوز running و متعلق به همان worker باشد. تراکنش دیتابیس در زمان انتظار پاسخ مدل باز نگه داشته نمی‌شود.

## محدودیت‌ها
این پیاده‌سازی همچنان worker را داخل فرایند API اجرا می‌کند. برای مقیاس‌پذیری چندسرویسی، صف مستقل و worker جداگانه لازم است. timeout سمت provider و cancellation در این مرحله اضافه نشده‌اند.

## بازیابی پس از راه‌اندازی مجدد فرایند

وضعیت صف و مالکیت Task در پایگاه داده ذخیره می‌شود؛ بنابراین فرایند تازه به حافظه Worker قبلی وابسته نیست. در هر چرخه Worker، پیش از claim بعدی، Taskهای دارای وضعیت `running` و lease منقضی‌شده بررسی می‌شوند. Task زیر سقف تلاش به `queued` برمی‌گردد و Task رسیده به سقف تلاش `failed` می‌شود. lease معتبر و منقضی‌نشده دست‌نخورده می‌ماند.

آزمون یکپارچه PostgreSQL برای این مسیر یک مفسر Python جداگانه اجرا می‌کند. فرایند آزمون، وضعیت‌های باقی‌مانده از Worker قبلی را در پایگاه داده آزمایشی ثبت می‌کند؛ فرایند تازه با شناسه فرایندی مستقل تابع بازیابی را اجرا می‌کند و وضعیت Task و رویداد ممیزی را بررسی می‌کند. این آزمون مرز بین دو فرایند را پوشش می‌دهد، اما شبیه‌سازی ارسال SIGKILL هنگام درخواست واقعی مدل یا آزمون پایگاه داده عملیاتی نیست.

## تضمین تحویل و محدودیت تکرار

این سازوکار اجرای دقیقاً یک‌باره درخواست خارجی را تضمین نمی‌کند. اگر ارائه‌دهنده درخواست را پردازش کرده باشد اما فرایند پیش از ذخیره نتیجه متوقف شود، پس از انقضای lease ممکن است همان درخواست دوباره ارسال شود. در این نسخه، کلید idempotency سمت ارائه‌دهنده، outbox تراکنشی و لغو امن درخواست خارجی وجود ندارد؛ بنابراین رفتار بازیابی می‌تواند به تکرار فراخوانی مدل منجر شود. برای کارهای دارای اثر جانبی، پیش از افزودن ابزارهای اجرایی باید لایه idempotency و سیاست retry مشخص شود.

## محدوده اعتبار آزمون

آزمون PostgreSQL در GitHub Actions از سرویس موقت PostgreSQL 16 استفاده می‌کند و migrationها را پیش از آزمون اجرا می‌کند. موفقیت آن، رفتار روی نسخه آزمایشی PostgreSQL را نشان می‌دهد؛ نه اجرای migration یا سلامت پایگاه داده Supabase عملیاتی را.
