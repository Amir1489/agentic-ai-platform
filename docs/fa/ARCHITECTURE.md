# معماری و تصمیم‌های مهندسی

## پشته فنی فعلی
- رابط کاربری: React 19، TypeScript، Vite، Motion و Lucide.
- میزبانی رابط کاربری: GitHub Pages.
- بک‌اند: FastAPI و SQLAlchemy روی Render.
- پایگاه داده: PostgreSQL روی Supabase.
- احراز هویت: توکن Bearer؛ ذخیره هش توکن در پایگاه داده و هش گذرواژه با Argon2.
- ارائه‌دهنده هوش مصنوعی: نقطه پایانی Chat Completions سازگار با OpenAI که فقط در بک‌اند پیکربندی می‌شود.

## جریان درخواست
مرورگر ← رابط GitHub Pages ← API مبتنی بر HTTPS در FastAPI روی Render ← PostgreSQL در Supabase.

برای تولید پاسخ چت، FastAPI با استفاده از کلید محرمانه سمت سرور به ارائه‌دهنده هوش مصنوعی درخواست می‌فرستد. مرورگر نباید کلید ارائه‌دهنده را دریافت کند.

## سطح فعلی API
- `GET /api/health`
- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/me`
- `POST /api/auth/logout`
- `GET/POST /api/projects`
- `DELETE /api/projects/{project_id}`
- `GET/POST /api/conversations`
- `GET /api/conversations/{conversation_id}/messages`
- `POST /api/conversations/{conversation_id}/messages`
- `DELETE /api/conversations/{conversation_id}`

تمام مسیرهای پروژه و گفت‌وگو به نشست معتبر نیاز دارند و داده‌ها را بر اساس شناسه مالک محدود می‌کنند.

## کنترل‌های امنیتی فعلی
- هش گذرواژه با پیکربندی پیشنهادی Argon2 در pwdlib.
- تولید توکن نشست با مولد تصادفی امن رمزنگارانه.
- ذخیره‌سازی فقط هش SHA-256 توکن نشست در پایگاه داده.
- بررسی انقضای نشست در درخواست‌های احراز هویت‌شده.
- بررسی مالکیت پروژه و گفت‌وگو در سمت سرور.
- نگهداری اعتبارنامه‌های ارائه‌دهنده هوش مصنوعی فقط در بک‌اند.
- پیکربندی صریح مبدأهای مجاز CORS.

## تصمیم‌ها و موازنه‌ها
- اتصال ارائه‌دهنده هوش مصنوعی پشت یک adapter کوچک سمت سرور نگه داشته می‌شود تا از ارائه‌دهندگان سازگار پشتیبانی شود، بدون آنکه کلیدها افشا شوند.
- فرانت‌اند مستقل از ارائه‌دهنده است و فقط API پلتفرم را فراخوانی می‌کند.
- در صورت خطای ارائه‌دهنده، پیام کاربر به‌تنهایی ذخیره نمی‌شود: ابتدا پاسخ تولید و سپس هر دو پیام در یک تراکنش ذخیره می‌شوند.
- محیط اجرای اولیه محدود نگه داشته می‌شود؛ اجرای دلخواه کد یا shell نباید قابلیت عامل باشد.
- در CI از provider و ابزارهای شبیه‌سازی‌شده استفاده می‌شود تا آزمون‌ها قطعی و بدون هزینه خارجی باشند.
- Alembic برای مهاجرت طرح پایگاه داده استفاده می‌شود؛ SQLAlchemy `create_all` سامانه مهاجرت نیست.

## شکاف‌های شناخته‌شده
- توکن Bearer در `localStorage` مرورگر ذخیره می‌شود؛ پیش از انتشار عملیاتی، طراحی کوکی امن HttpOnly ترجیح دارد.
- محدودسازی نرخ و کنترل سوءاستفاده وجود ندارد.
- تأیید ایمیل و بازیابی گذرواژه وجود ندارد.
- پاک‌سازی خودکار نشست‌های منقضی وجود ندارد.
- تأیید نهایی اتصال زنده پایگاه داده/ارائه‌دهنده در همه گردش‌کارهای مخزن انجام نشده است.
- اجرای عامل، ابزار و گردش‌کار هنوز کامل نیست.

## API مدیریت عامل
- `GET /api/agents`: فهرست عامل‌های کاربر احراز هویت‌شده.
- `POST /api/agents`: ایجاد عامل با وضعیت `draft`.
- `PUT /api/agents/{id}`: ویرایش نام، توضیحات، دستورالعمل‌ها، مدل و وضعیت چرخه عمر.
- `DELETE /api/agents/{id}`: حذف عامل متعلق به کاربر.
- همه مسیرها نشست Bearer معتبر می‌خواهند و داده‌ها را با `owner_id` محدود می‌کنند.
- وضعیت `active` در مدیریت عامل به‌تنهایی به معنی اجرای worker یا ابزار نیست؛ اجرای مدل در بخش بعد توضیح داده شده است.

## سلامت و آمادگی
- `GET /api/health` سلامت فرایند را گزارش می‌کند و وابستگی‌ها را بررسی نمی‌کند.
- `GET /api/ready` یک `SELECT 1` سبک با engine تنظیم‌شده SQLAlchemy اجرا می‌کند و هنگام خطای پایگاه داده HTTP 503 می‌دهد. اطلاعات اتصال یا اعتبارنامه‌ها افشا نمی‌شوند.

## اجرای تک‌مرحله‌ای کار عامل
- `POST /api/agents/{agent_id}/tasks` برای عامل متعلق به کاربر با وضعیت `active` یک پاسخ مدل اجرا می‌کند.
- ورودی حداکثر ۸٬۰۰۰ نویسه، خروجی حداکثر ۱۲٬۰۰۰ نویسه و مهلت ارائه‌دهنده ۴۵ ثانیه است.
- رکورد کار وضعیت‌های `running`، `succeeded` یا `failed` را نگه می‌دارد. رویدادها تغییر وضعیت‌های `started`، `succeeded` و `failed` را ثبت می‌کنند.
- `GET /api/agents/{agent_id}/tasks` حداکثر ۵۰ کار اخیر را برمی‌گرداند.
- `GET /api/agents/{agent_id}/tasks/{task_id}/events` تاریخچه ممیزی کار را برمی‌گرداند.
- این قابلیت اجراکننده عمومی ابزار نیست: shell، مفسر کد، دریافت شبکه، اتصال خارجی یا اجرای ابزار دلخواه در دسترس نیست.
- شکاف‌های فعلی: اجرای هم‌زمان HTTP، نبود صف worker، لغو، بودجه هزینه/توکن، سیاست تلاش مجدد، بازیابی کار گیرکرده و گردش‌کار تأیید انسانی.

## وضعیت عمومی قابلیت‌ها
- `GET /api/capabilities` فقط مقادیر بولی `chat` و `agent_tasks` را بر اساس وجود کلید خصوصی `AI_API_KEY` برمی‌گرداند.
- این مسیر کلید، نشانی پایه، پاسخ ارائه‌دهنده یا مقدار محرمانه‌ای را افشا نمی‌کند. صفحه تنظیمات از آن برای نمایش وضعیت پیکربندی قابلیت‌های هوش مصنوعی استفاده می‌کند.

## مهاجرت پایگاه داده
- Alembic در `backend/migrations` پیکربندی شده است.
- نسخه اولیه از `Base.metadata.create_all` به‌عنوان خط پایه پذیرش تکرارپذیر استفاده می‌کند تا نصب‌های موجود حذف یا بازسازی نشوند؛ در پایگاه داده تازه جدول‌های مفقود را ایجاد می‌کند.
- Render پیش از اجرای Uvicorn دستور `alembic upgrade head` را اجرا می‌کند.
- مهاجرت پایه فقط رو به جلو است. تغییرات بعدی طرح باید با revisionهای صریح Alembic انجام شوند؛ `create_all` ستون‌های موجود را تغییر نمی‌دهد.
